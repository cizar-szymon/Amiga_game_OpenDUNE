# OpenDUNE for Amiga with a Warp card – what is new (10 November 2026)

OpenDUNE is an open re-creation of Dune II. This port is made for Amigas with a Warp
accelerator and its graphics card (Picasso96, 8-bit screen of 640x480 or more).
Two releases came out today: **0.52** and **0.53**.

Download: <https://github.com/cizar-szymon/Amiga_game_OpenDUNE> → `releases/amiga`
(`UnZip OpenDUNE-0.53.zip -d Work:Games`). The Dune II data files are not included.

## Release 0.52

- **Internet game for 2 or 3 players.** *Play on LAN → INTERNET GAME*: a list of the
  games waiting, a four-character code for each game, a password if you want one.
  The Amigas meet on a game server, so nothing has to be set on the router.
- **Bug reports from the game.** F10 on the map screen opens a window for your e-mail
  address and a description (up to 1000 characters) and sends them with the report
  files to the game server. It needs a running TCP/IP stack.
- **Out-of-step report.** If the games of the players ever differ, the maker of the
  game can send the game logs of all players the same way.
- **Fair starts in multiplayer.** The start positions are chosen from the map so that
  every player has about the same rock to build on.
- **Slabs and walls in multiplayer** are placed next to the base of the player who
  builds them, whoever ordered one last.

## Release 0.53

- **A clean font.** `font=clean` in opendune.ini (or the Tool Type `FONT=clean`) gives
  plain, easy to read letters in the menus, windows, messages and on the top bar.
  The game's own font stays the default.
- **"Your base is under attack"** is heard by the player whose building is hit.

## How it was tested

- Three machines playing through the game server – an Amiga 4000 with a Warp 7060, an
  Amiga 1200 with a Warp 1260 (both 68060 at 100 MHz) and WinUAE: 11.5 minutes of
  play, the games stayed identical (checksums every 5 seconds, no difference).
- A test battle of three houses with 58 units and 30 buildings: the games stayed
  identical on all three machines.
- CPU time on the Amiga 4000 during that battle: drawing the map 56 %, sending the
  picture to the card 22 %, game logic 11 %, idle 7 %; about 52 frames a second.
  In a quiet scene the CPU is idle 71 % of the time.

All three machines were on one home network, going out to the server's public address;
a game between two different internet connections has not been tried yet.

## What comes next

Drawing the map directly in the graphics card's memory, once the Warp card has a new
FPGA function for it. The battle above shows why: drawing and sending the picture take
almost four fifths of the CPU time when many units fight.
